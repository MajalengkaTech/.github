# Kebijakan Keamanan

## Dukungan versi

Mejalengka-Tech berusaha menangani masalah keamanan
pada versi proyek yang masih didukung.

Status dukungan dapat berbeda pada setiap repository.
Silakan periksa README dan dokumentasi repository terkait.

## Melaporkan masalah keamanan

Jangan melaporkan masalah keamanan melalui issue publik.

Laporkan masalah keamanan secara privat melalui:

- Email: `[tambahkan-email-keamanan]`
- GitHub Security Advisories, jika tersedia.
- Formulir privat: `[tambahkan-tautan-formulir]`

## Informasi yang perlu disertakan

Sertakan informasi berikut jika memungkinkan:

- Nama repository.
- Versi atau commit yang terdampak.
- Penjelasan masalah.
- Langkah untuk mengulang masalah.
- Dampak yang mungkin terjadi.
- Bukti konsep atau contoh eksploitasi yang aman.
- Saran perbaikan, jika ada.
- Informasi kontak untuk komunikasi lanjutan.

Jangan mengirimkan:

- Password.
- Token akses.
- Kunci API.
- Data pribadi.
- Data pengguna asli.
- Data pemerintah yang bersifat rahasia.

## Proses penanganan

Setelah laporan diterima, pengelola akan:

1. Mengonfirmasi penerimaan laporan.
2. Memeriksa dan memvalidasi masalah.
3. Menentukan tingkat keparahan.
4. Menyiapkan perbaikan.
5. Menguji perbaikan.
6. Merilis pembaruan jika diperlukan.
7. Menginformasikan pelapor setelah masalah ditangani.

Kami berusaha merespons laporan dalam waktu yang wajar,
tetapi waktu penanganan dapat berbeda berdasarkan tingkat kesulitan
dan dampak masalah.

## Pengungkapan masalah

Kami meminta pelapor untuk tidak mengungkapkan masalah keamanan
kepada publik sebelum perbaikan tersedia.

Setelah perbaikan tersedia, pengungkapan dapat dilakukan secara terkoordinasi
dengan mempertimbangkan keamanan pengguna dan kebutuhan proyek.

## Keamanan kontributor

Kontributor wajib:

- Tidak mengirimkan rahasia ke repository.
- Tidak mengunggah data pribadi tanpa izin.
- Tidak menyertakan token atau credential dalam kode.
- Menggunakan dependency yang terpercaya.
- Melaporkan masalah keamanan secara privat.
- Menghapus informasi sensitif dari log dan contoh kode.

## Insiden keamanan

Jika terjadi insiden keamanan yang memengaruhi pengguna,
maintainer dan Core Team akan:

- Membatasi dampak insiden.
- Mengamankan sistem terkait.
- Menentukan penyebab insiden.
- Memperbaiki kelemahan.
- Memberi informasi yang diperlukan kepada pihak terdampak.
- Mendokumentasikan pembelajaran dari insiden tersebut.

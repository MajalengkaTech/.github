# Panduan Kontribusi

Terima kasih telah tertarik untuk berkontribusi pada Mejalengka-Tech.

Semua bentuk kontribusi sangat dihargai, termasuk kode, desain, dokumentasi,
pengujian, pelaporan bug, ide, dan masukan.

## Sebelum berkontribusi

Sebelum memulai, silakan:

1. Membaca README pada repository yang ingin Anda kontribusikan.
2. Membaca Kode Etik Mejalengka-Tech.
3. Memeriksa issue yang sudah ada.
4. Memastikan ide Anda belum pernah dibahas.
5. Membuat issue terlebih dahulu untuk perubahan besar.

## Jenis kontribusi

Anda dapat berkontribusi dengan cara berikut:

- Melaporkan bug.
- Mengusulkan fitur.
- Memperbaiki dokumentasi.
- Memperbaiki desain.
- Menulis kode.
- Menambahkan pengujian.
- Memperbaiki aksesibilitas.
- Membantu menerjemahkan konten.
- Meninjau pull request.
- Membantu pengguna lain.

## Melaporkan bug

Gunakan issue dengan kategori bug jika tersedia.

Sertakan informasi berikut:

- Penjelasan masalah.
- Langkah untuk mengulang masalah.
- Hasil yang diharapkan.
- Hasil yang terjadi.
- Sistem operasi dan browser, jika relevan.
- Versi proyek yang digunakan.
- Screenshot atau log, jika tersedia.
- Contoh kode minimal, jika relevan.

Jangan sertakan password, token, data pribadi, atau informasi rahasia.

## Mengusulkan fitur

Sebelum mengusulkan fitur, jelaskan:

- Masalah yang ingin diselesaikan.
- Siapa yang akan mendapatkan manfaat.
- Solusi yang diusulkan.
- Alternatif yang sudah dipertimbangkan.
- Dampak terhadap proyek.
- Contoh penggunaan.

Untuk fitur besar, diskusikan terlebih dahulu melalui issue atau Discussions.

## Alur pull request

1. Fork repository jika Anda bukan anggota dengan akses tulis.
2. Buat branch baru.
3. Lakukan perubahan secara terfokus.
4. Tambahkan atau perbarui pengujian jika diperlukan.
5. Perbarui dokumentasi jika perubahan memengaruhinya.
6. Pastikan pemeriksaan otomatis berhasil.
7. Buat pull request.
8. Jelaskan perubahan yang dibuat.
9. Tanggapi proses review.
10. Tunggu persetujuan maintainer.

## Penamaan branch

Gunakan nama branch yang singkat dan jelas:

```text
feature/nama-fitur
fix/nama-masalah
docs/nama-dokumentasi
refactor/nama-perubahan
chore/nama-pekerjaan
```

Contoh:

```text
feature/button-komponen
fix/warna-mode-gelap
docs/panduan-instalasi
```

## Format commit

Gunakan format berikut:

```text
tipe: deskripsi singkat
```

Tipe commit yang umum:

- `feat`: menambahkan fitur.
- `fix`: memperbaiki bug.
- `docs`: mengubah dokumentasi.
- `style`: mengubah format tanpa mengubah fungsi.
- `refactor`: merapikan kode.
- `test`: menambahkan atau memperbaiki pengujian.
- `chore`: pekerjaan pemeliharaan.

Contoh:

```text
feat: menambahkan komponen tombol
fix: memperbaiki warna teks pada mode gelap
docs: memperbarui panduan instalasi
```

## Standar pull request

Pull request harus berisi:

- Ringkasan perubahan.
- Masalah yang diselesaikan.
- Cara menguji perubahan.
- Dampak perubahan.
- Screenshot atau rekaman layar jika menyangkut tampilan.
- Catatan tambahan untuk reviewer.

Pull request yang terlalu besar dapat diminta untuk dipecah
menjadi beberapa pull request yang lebih kecil.

## Review

Reviewer dapat meminta:

- Perubahan kode.
- Penambahan pengujian.
- Perbaikan dokumentasi.
- Perbaikan aksesibilitas.
- Penjelasan tambahan.

Review ditujukan untuk meningkatkan kualitas proyek,
bukan untuk menyerang kontributor.

## Standar umum

Setiap kontribusi diharapkan memperhatikan:

- Keterbacaan kode.
- Dokumentasi.
- Keamanan.
- Aksesibilitas.
- Performa.
- Kompatibilitas.
- Kemudahan pemeliharaan.
- Privasi pengguna.
- Dampak terhadap masyarakat.

## Lisensi kontribusi

Dengan mengirimkan kontribusi, Anda menyatakan bahwa:

- Anda memiliki hak untuk mengirimkan kontribusi tersebut.
- Kontribusi tidak sengaja melanggar hak pihak lain.
- Kontribusi dapat digunakan sesuai lisensi repository terkait.

## Pertanyaan

Jika Anda memiliki pertanyaan, buat Discussion atau issue,
atau hubungi pengelola melalui kanal komunikasi resmi.
